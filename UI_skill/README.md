# UI Skill 总入口

这个文件夹记录在 **测试版 UI 实装过程中积累的执行经验**。

当前代码（test0.3）是验证性原型，不是最终产品。所有 skill 的目的是：

- 记录「做了才知道」的实装规律
- 避免下次重复踩同一个坑
- 供正式版本实装时参考，而不是照抄

---

## 文件结构

- `figma-to-code.md`  
  Figma → 代码的还原流程、常见陷阱、资产处理

- `state_machine.md`  
  完整状态机：视图切换规则、可操作范围、已验证的实装注意事项

- `screen_patterns.md`  
  各页面的角色与结构——哪些是正式状态、哪些是过渡帧、哪些还没定

- `design_language.md`  
  视觉与交互气质方向——已确认的 + 还在探索的

- `layout_and_layers.md`  
  Figma 图层结构与页面版面的组织方式

- `naming.md`  
  Frame、Group、Section、组件图层的命名习惯

- `states_and_annotations.md`  
  多状态页面、滚动页面、上下帧关系备注

- `components_and_icons.md`  
  返回按钮、图标、动作区、可复用控件的约定

---

## 使用方式

写新规则时：先判断它属于哪类，写进对应文件。**不要同一条规则在多个文件都写详细版本。**

有跨文件的联系，在次要文件里做短引用即可。

---

## 与 MAP_SPEC 的关系

`MAP_SPEC` 定义项目定位与核心逻辑。`UI_skill/` 是实装过程中的执行经验。

两者冲突时：先回到 MAP_SPEC，skill 服从总纲。

---

## 经验写入规则（AI 必读）

- 每次从实装中发现新规律，**立即写进对应 skill 文件**，不等用户提醒
- 同时写进 memory（跨会话记忆）和 UI_skill（项目级文档）
- 写时区分：「已验证有效」vs「推测/待验证」
- 缺素材时先查 `assets/figma/` 和 `素材0.x/`，找到再用，找不到再问

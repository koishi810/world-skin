# 界面类型规范

这个文件用于记录当前已经形成稳定方向的几类界面。  
它回答的不是“某个图层叫什么”，而是：

- 这个界面在产品里承担什么角色
- 哪些 Frame 是正式状态，哪些只是过渡帧
- 推荐使用怎样的结构
- 后续继续扩展时，哪些关系应尽量保持

## 1. 主界面 / Main Screen

### 页面角色

主界面是项目的默认地图状态，也是用户进入应用后最核心的停留页面。  
它应优先展示 `World Skin` 本身，而不是让控件成为主角。

### 当前状态约定

#### `Home / 01 默认`

- 类型：`正式状态`
- 用途：主界面的默认地图状态
- 说明：这是主界面的基础落点，后续其它展开、切换和采样流程都应能回到这里

#### `Transition / 02 展开中`

- 类型：`过渡帧`
- 用途：主界面点击下方功能模块或头像后的展开显示状态
- 说明：它用于演示从地图默认态进入其它内容层的过渡，不代表独立页面

### 推荐结构

- `Background / 背景层`
- `Overlay / 底部功能遮罩`
- `功能模块`
  - `Button / 地图`
  - `Button / 记录`
  - `Button / 个人`
- `Avatar / 头像框`
- `Timeline / 时间轴`
- `Controls / 地图工具`
- `Overlay / 下拉遮罩`
- `System / Status Bar`

### 使用原则

- 地图皮肤永远是主视觉。
- 底部功能模块应轻量存在，不要做成强卡片式导航。
- 中间的 `记录` 入口负责进入采样流程，但主交互不应被画成普通 CTA。
- 头像既是身份入口，也可作为进入个人展开态的触发点。
- `Transition / 02 展开中` 只服务动效说明；实装时可以被合并进真实转场逻辑。

## 2. Feature / 个人详情展开

### 页面角色

`Feature` 这一组当前主要用于说明从主界面进入个人详情时的展开方式。  
它不是独立一级页面，而是主界面向个人详情内容层过渡时的表现。

### 当前状态约定

#### `Feature / 04 大头像出现（动画中间帧`

- 类型：`过渡帧`
- 用途：头像放大动画的中间帧
- 说明：只用于展示头像从主界面状态向详情页展开时的中间关系

#### `Feature / 05 大头像 + 标记`

- 类型：`稳定目标状态`
- 用途：个人详情信息展开后的完整状态
- 说明：头像、姓名、当前倾向、最近记录和底部动作已全部进入正式布局

### 推荐结构

- `Background / 背景层`
- `Overlay / 下拉遮罩`
- `Overlay / 切换遮罩`
- `Profile / 雾化区域`
- `Content / 个人资料主体`
  - `Profile / Hero`
  - `Header / 头部`
  - `Section / 当前倾向`
  - `Section / 最近记录`
  - `Actions / 底部操作`
- `Header / 返回按钮`
- `System / Status Bar`

### 使用原则

- 头像展开是这个界面的主要动势，不要让文本比头像更早抢走主导权。
- `04` 只服务过渡，`05` 才是展开后的正式内容结构。
- 为了原型补间而加入的透明占位层，可以留在 Figma 中，但实装时不要求照搬。
- 个人详情展开后，应保持与文字型信息页一致的阅读秩序，但密度可以低于设置页。

## 3. Personal / 个人界面

### 页面角色

`Personal` 用于表达“个人数据层”，它与公共 `World Map` 区分开，但仍然保留同一套地图世界观。

### 当前状态约定

#### `Personal / 01 个人默认`

- 类型：`正式状态`
- 用途：个人地图页的默认状态
- 说明：点击地图后返回这个页面；它是个人视图中的默认落点

#### `Personal / 01 个人`

- 类型：`展开状态`
- 用途：个人界面点击底部状态栏或头像后的展开显示状态
- 说明：它与主界面的展开逻辑相近，但额外引入记录页的进入关系

#### `Personal / 02 记录`

- 类型：`正式状态`
- 用途：个人记录统计页
- 说明：用于展示个人记录的概要、时间层和感觉分布

### 推荐结构

#### 个人地图态

- `Background / 背景层`
- `Overlay / 底部功能遮罩`
- `功能模块`
- `Avatar / 头像框`
- `Timeline / 时间轴`
- `Overlay / 下拉遮罩`
- `System / Status Bar`

#### 个人记录页

- `Background / 背景层`
- `Overlay / 切换遮罩`
- `Content / 记录可视化`
  - `Header / 头部`
  - `Section / 概要`
  - `Section / 时间层`
  - `Section / 感觉分布`
- `System / Status Bar`

### 使用原则

- `Personal` 代表本机个人记录，不应被设计成社交主页。
- `Personal / 01 个人默认` 仍然首先是地图页，而不是信息面板页。
- `Personal / 02 记录` 可以提高信息密度，但仍要保持项目的安静、低噪声气质。
- 记录统计内容应服务“理解自己的感知轨迹”，不要滑向排行榜、成就或量化评估界面。

## 4. Settings / 设置界面

### 页面角色

设置页是典型的文字型信息页，用于承载低频但需要清晰组织的系统选项。  
它可以比主界面更功能化，但仍要保持同一套视觉世界。

### 当前状态约定

#### `Settings / FULL`

- 类型：`完整结构稿`
- 用途：展示整张长页的完整内容组织

#### `Settings / Viewport Top`

- 类型：`正式进入状态`
- 用途：设置页进入时的顶部 viewport

#### `Settings / Viewport Bottom`

- 类型：`滚动状态`
- 用途：设置页滚动到底部时的 viewport

### 推荐结构

- `System / Status Bar`
- `Background / 背景层`
- `Overlay / 切换遮罩`
- `Header / 返回按钮`
- `Content / 设置主体`
  - `Header / 头部`
  - `Section / 表示`
  - `Section / 记录`
  - `Section / 通知`
- `Scroll / Track`
- `Scroll / Thumb`

### 使用原则

- 设置页允许信息密度更高，但不能失去呼吸感。
- 顶部返回入口应固定在滚动内容之外。
- `FULL` 用于看结构，`Viewport Top / Bottom` 用于表达真实设备中的页面状态。
- section、row、divider 应各自归位，不要把大量文字和分割线散在最外层。

## 5. Sense / 采样流程

### 页面角色

`Sense` 用于表达从主界面进入采样、完成呼吸、进入感知词选择，再到记录写入完成的连续过程。  
它包含正式状态，也包含为了说明复杂动效而保留的中间帧。

### 当前状态约定

- `Sense / 02 接触层显影`：过渡帧
- `Sense / 03 雾面扩散`：过渡帧
- `Sense / 04 长按区凝结`：正式待机状态
- `Sense / 05 长按开始（吸气`：中间帧，表示深呼吸达到最大之后的效果
- `Sense / 06 长按结束`：过渡帧，表示呼吸结束，之后进入情绪选择界面
- `Sense / 07 情绪选择1（中间帧`：过渡帧，表示第一轮感知词从雾面中开始浮现
- `Sense / 08 情绪选择1`：正式选择状态，表示第一轮感知词已稳定出现
- 后续同名 `Sense / 07 情绪选择1（中间帧`：过渡帧，表示第一轮选择结束后向下一轮切换
- `Sense / 09 情绪补选`：正式选择状态，表示第二轮补选词已稳定出现
- `Sense / 10 情绪补选（中间帧`：过渡帧，表示补选结束后向记录完成切换
- `Sense / 10 记录完成`：正式收束状态，表示本次记录已写入完成

### 使用原则

- `02–03` 只服务长按前的显影过渡。
- `04` 是真正可供用户开始长按的落点。
- `05–06` 用于说明采样中的呼吸过程与结束收束。
- `07–10` 用于说明采样完成后的感知词选择流程：先选择、再补选、最后完成写入。
- 情绪词页面本质上是“感知词选择”，不是情绪分类页；用户看到的是接近身体感受的短词，而不是轴名或算法说明。
- 第一轮和补选页都允许保留独立中间帧，以保证词团显影、替换和退场时仍属于同一套雾系统。
- `记录完成` 应作为流程的安静落点，不要做成普通成功弹窗或强反馈页。
- 实装时可以根据真实动画逻辑合并或重写中间帧，不要求逐帧照搬。

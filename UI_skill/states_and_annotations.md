# 页面状态与备注

## 同一页面的多个状态

如果同一个页面有多个状态或多个 viewport：

- 尽量使用同一套图层结构。
- 不同状态之间，优先保持相同的外层组织方式。

例：

- `Settings / FULL`
- `Settings / Viewport Top`
- `Settings / Viewport Bottom`

如果某个状态因为画面内容不同，确实缺少某个图层，也要尽量保持外围结构和命名逻辑一致，不要另起一套。

## 上下帧备注

中间帧如果需要说明前后关系，不建议把 `From / To` 全部写进图层名里，避免命名过长。

统一在对应 Frame 的底部外侧添加小型文字备注：

- `From: 00 Viewport Top`
- `To: 02 Viewport Bottom`

备注不进入实际 UI 画面内部，只作为设计文件说明使用。

Frame 本身仍按统一规则命名：

- `Settings / Scroll / 00 Viewport Top`
- `Settings / Scroll / 01 Mid`
- `Settings / Scroll / 02 Viewport Bottom`

底部备注建议使用低存在感样式：

- 字号：`10–12px`
- 颜色：白色 35–45% 或中性灰
- 对齐方式：左对齐，跟 Frame 左边缘对齐
- 与 Frame 底部距离：`8–16px`

示例：

- Frame 名：`Settings / Scroll / 01 Mid`
- 底部备注：
  - `From: 00 Viewport Top`
  - `To: 02 Viewport Bottom`

## 长页面表达

如果一个页面本质上是滚动页，可以同时保留：

- 一张完整长图：用于看完整结构
- 一张顶部 viewport：用于看初始进入状态
- 一张底部 viewport：用于看滚动到底部状态

这样能同时表达：

- 页面全貌
- 真实设备中的裁切关系
- 页面在滚动中的状态变化

## Test 页的用途备注

如果某个页面仍处于探索、验证或测试阶段，可以在 `test` 页中为对应 Frame 添加“用途备注”，帮助后续理解它当前在验证什么。

这些备注只服务于设计过程，不代表最终产品结构、最终页面命名或最终交互方案。

推荐做法：

- 备注放在对应 Frame 的外侧，不进入真实 UI 画面内部
- 文案使用“测试用途：...”这类过程性表述
- 内容只说明该 Frame 当前在验证什么，不提前把方案写死
- 同一组测试页面尽量保持相同的备注位置和样式

建议样式：

- 字号：`10–12px`
- 颜色：白色 `35–45%` 或中性灰
- 对齐方式：左对齐，跟 Frame 左边缘对齐
- 与 Frame 底部距离：`8–16px`

示例：

- `测试用途：设置长页的完整结构`
- `测试用途：设置页进入时的顶部 viewport`
- `测试用途：头像放大动画的中间帧`

## 真实 UI 结构与原型辅助层

设计文件里可以同时存在两类结构：

### 1. 真实 UI 结构

这类图层用于表达最终产品里确实存在的页面、区域、控件或状态。

例如：

- 页面主体
- 顶部返回入口
- 最终可交互区域
- 正式进入某个流程后的稳定状态

真实 UI 结构在后续实现时应作为主要参考。

### 2. 原型辅助层 / 原型辅助帧

这类图层或 Frame 只用于让 Figma 原型中的动效更容易演示、补间更连续，或帮助设计过程中观察中间关系。

例如：

- 为了让 `Smart Animate` 能接上的透明占位层
- 只用于解释动画路径的中间帧
- 为了展示前后变化而临时保留的过渡状态

这些结构：

- 可以存在于设计文件中
- 应在备注里说明它们的用途
- 不代表最终产品必须逐层、逐帧照搬实现
- 实装时可以根据真实交互与代码结构删减、合并或重写

如果某一层只服务原型补间，不服务真实界面，应优先在：

- 图层命名
- Frame 备注
- 或本文件中的状态说明

里把这一点写清楚，避免后续把“演示结构”误认为“产品结构”。

## Contact / 接触层状态序列

当某个交互本身依赖连续变化，而不是单一静态界面时，可以在 `test` 页中保留多张中间帧来说明状态演化。

以感觉采样为例，可按需要拆成：

- 接触层开始显影
- 雾面扩散 / 地图被读取
- 中央可按区域逐渐凝结
- 长按开始
- 长按进行中
- 采样接近完成

这些中间帧用于验证动效方向、层级顺序和画面关系，不代表最终实现一定逐帧如此拆分。

### 当前 Sense 状态序列的用途约定

当前 `Sense / 02–06` 的用途按以下方式理解：

#### `Sense / 02 接触层显影`

- 类型：`过渡帧`
- 用途：进入长按采样前，接触层开始显影
- 说明：只用于提示“这里即将形成可交互区域”，不代表已经开始采样

#### `Sense / 03 雾面扩散`

- 类型：`过渡帧`
- 用途：承接 `02` 与 `04`，表现雾面扩散、可交互区域逐渐从环境中浮现
- 说明：这是为了动画连续性补出的中间状态，不是独立的最终页面

#### `Sense / 04 长按区凝结`

- 类型：`稳定目标状态`
- 用途：点击主界面功能模块中间“记录”按钮后，最终会达到的待机状态
- 说明：此时用户还没有开始长按；这是“可以开始长按”的正式落点

#### `Sense / 05 长按开始（吸气`

- 类型：`中间帧`
- 用途：表现深呼吸扩张到最大之后的画面
- 说明：它用于表达呼吸过程中的峰值，不等同于独立页面

#### `Sense / 06 长按结束`

- 类型：`过渡帧`
- 用途：表现呼吸结束后的收束状态
- 说明：其后应进入情绪选择界面；它是采样流程结束到后续选择流程之间的过渡状态

#### `Sense / 07 情绪选择1（中间帧`

- 类型：`过渡帧`
- 用途：第一轮感知词选择出现前的显影状态
- 说明：词团已经开始从环境中浮现，但尚未进入稳定可选状态

#### `Sense / 08 情绪选择1`

- 类型：`稳定目标状态`
- 用途：第一轮感知词选择的正式界面
- 说明：用于让用户选择当前最接近体感的词；当前示例文案为 `いまの感覚に近い言葉を選ぶ`

#### 后续同名 `Sense / 07 情绪选择1（中间帧`

- 类型：`过渡帧`
- 用途：第一轮选择结束后，词团向下一轮内容切换的中间状态
- 说明：它服务于词团退场与下一轮补选显影之间的连续动效，不代表新的业务页面

#### `Sense / 09 情绪补选`

- 类型：`稳定目标状态`
- 用途：第二轮感知词补选的正式界面
- 说明：用于把第一轮结果继续收窄到更接近当下的词；当前示例文案为 `もう少しだけ近いものを選ぶ`

#### `Sense / 10 情绪补选（中间帧`

- 类型：`过渡帧`
- 用途：补选结束后，词团退场并准备进入记录完成状态
- 说明：它用于连接补选页与完成页，避免词组突然消失

#### `Sense / 10 记录完成`

- 类型：`稳定目标状态`
- 用途：提示本次记录已经写入完成
- 说明：当前示例文案为 `記録されました`；视觉上应作为安静收束，而不是普通成功弹窗

### 使用原则

- `02` 与 `03` 主要服务动画衔接，不应被误解为正式业务页面。
- `04` 是长按前的关键稳定状态，是这组序列里最接近真实 UI 落点的一帧。
- `05` 与 `06` 主要服务采样过程中的动效表达，实装时可以按真实动画逻辑重写，不要求逐帧照搬。
- `07` 之后进入的是多轮感知词选择流程，不应再被解释为采样中状态。
- 第一轮选择、补选和记录完成都属于真实业务流程；其中穿插的中间帧只服务原型动效表达。
- 选择词应保持日文短词风格，不显示主观轴名、内部参数或算法解释。
- `记录完成` 是这段流程的最终落点；如果后续继续扩展第三轮选择，也应在进入完成页前补齐相应过渡说明。
- 如果后续继续补中间帧，应优先写清：
  - 它是正式状态还是过渡帧
  - 它承接哪一帧、通向哪一帧
  - 它是否需要在真实产品中保留
